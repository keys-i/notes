# Tutorial 1 — Dependencies and SQL

## Attribute closure drill

Let $R(A,B,C,D,E)$ have:

$$
F=\{A\rightarrow BC,\ C\rightarrow D,\ D\rightarrow E\}
$$

To compute $A^+$:

1. start with $\{A\}$
2. apply $A\rightarrow BC$ to add $B,C$
3. apply $C\rightarrow D$ to add $D$
4. apply $D\rightarrow E$ to add $E$

Therefore $A^+=\{A,B,C,D,E\}$ and $A$ is a candidate key

When testing minimality, remove one attribute at a time from a composite
superkey and recompute the closure

## SQL pattern drill

### At least one

Use `EXISTS` when only existence matters

```sql
SELECT s.student_id, s.name
FROM student AS s
WHERE EXISTS (
  SELECT 1
  FROM enrolment AS e
  WHERE e.student_id = s.student_id
    AND e.mark >= 85
);
```

### None

Change `EXISTS` to `NOT EXISTS`

### Every required row

Use double `NOT EXISTS` or compare counts only when duplicate and null
semantics are controlled

## Check your answer

- does every selected non-aggregate column appear in `GROUP BY`
- is a row predicate in `WHERE` and a group predicate in `HAVING`
- could a join duplicate rows before an aggregate
- does the query handle an empty required set correctly
- are null comparisons expressed with `IS NULL` rather than `= NULL`
