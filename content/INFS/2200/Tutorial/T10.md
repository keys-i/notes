# Tutorial 10 — Transaction Schedules

## Conflict table method

For each data item, list operations in schedule order and compare operations
from different transactions

```text
r1(X)  w2(X)  w1(Y)  r2(Y)
```

Conflicts give:

- `r1(X)` before `w2(X)` → $T_1\rightarrow T_2$
- `w1(Y)` before `r2(Y)` → $T_1\rightarrow T_2$

The acyclic graph has serial order $T_1,T_2$

If another conflict added $T_2\rightarrow T_1$, the cycle would make the
schedule not conflict-serialisable

## Recoverability method

Track every reads-from relationship

If $T_2$ reads a value written by $T_1$:

- recoverable requires `commit1` before `commit2`
- cascadeless requires `commit1` before that read
- strict requires no read or write of the item before `commit1` or `abort1`

## Anomaly method

Write the initial value and simulate every read and write, keeping each
transaction's local values separate from database values

This exposes lost updates and dirty reads that are easy to miss by inspection

## Final answer format

State the property, give the decisive edge or reads-from ordering, then state
the consequence and any equivalent serial order
