# Tutorial 4 — Constraints

## Choose the narrowest mechanism

| Rule | Best starting point |
| --- | --- |
| Mark is from 0 to 100 | `CHECK` |
| Student email is unique | `UNIQUE` |
| Enrolment needs an existing student | `FOREIGN KEY` |
| Every row has a course code | `NOT NULL` |
| A supervisor has at most five active students | Trigger or redesigned relation with transactional enforcement |

## Build a declarative solution

```sql
CREATE TABLE course (
  course_id text PRIMARY KEY,
  title text NOT NULL,
  units integer NOT NULL CONSTRAINT course_units_positive CHECK (units > 0)
);
```

Then test the boundary values as well as a normal value

## Trigger reasoning

Before writing a trigger, state:

1. event and timing
2. row-level or statement-level execution
3. invariant being protected
4. behaviour for multi-row statements
5. concurrent transactions that could pass the same check
6. expected failure and rollback behaviour

A `SELECT COUNT(*)` trigger check can still race unless locking or a stronger
database design serialises competing changes

## Deferral scenario

Use a deferrable relationship when a transaction must temporarily create an
invalid intermediate state while its final committed state is valid
