# Practical 3 — Sequences and Triggers

## Two cooperating objects

A sequence produces numeric values independently of a table, while a trigger
runs a function automatically for a table event

The practical connects them so identifiers are assigned before each insert

## Employee number sequence

```sql
CREATE SEQUENCE EMPNO_SEQ
    MINVALUE 1000
    MAXVALUE 9999
    INCREMENT BY 1
    START WITH 1000;
```

Create a trigger function that writes the next sequence value into the pending
row represented by `NEW`

```sql
CREATE OR REPLACE FUNCTION generate_empno()
RETURNS TRIGGER AS $$
BEGIN
    NEW.EMPNO := nextval('EMPNO_SEQ');
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER BI_EMP
BEFORE INSERT ON EMP
FOR EACH ROW
EXECUTE FUNCTION generate_empno();
```

`BEFORE INSERT` allows the function to change the row before PostgreSQL stores
it, and `RETURN NEW` passes that changed row back to the insert

## Department number sequence

```sql
CREATE SEQUENCE DEPTNO_SEQ
    MINVALUE 50
    MAXVALUE 99
    INCREMENT BY 10
    START WITH 50;
```

The corresponding trigger can assign `NEW.DEPTNO` when an insert omits the
department number

```sql
INSERT INTO DEPT (DNAME, LOCATION)
VALUES ('Training', 'Brisbane');
```

The sequence supplies `50`, followed by `60`, `70` and so on until its maximum

## Inspect database metadata

```sql
SELECT
    sequence_schema,
    sequence_name,
    start_value,
    minimum_value,
    maximum_value,
    cycle_option
FROM information_schema.sequences
ORDER BY sequence_schema, sequence_name;
```

```sql
SELECT
    t.tgname AS trigger_name,
    c.relname AS table_name
FROM pg_trigger AS t
JOIN pg_class AS c ON t.tgrelid = c.oid
WHERE NOT t.tgisinternal;
```

Filtering `tgisinternal` removes PostgreSQL's own system triggers from the
second result

## Remove objects deliberately

```sql
DROP TRIGGER IF EXISTS BI_EMP ON EMP;
DROP SEQUENCE IF EXISTS EMPNO_SEQ;
DROP TRIGGER IF EXISTS BI_DEPT ON DEPT;
DROP SEQUENCE IF EXISTS DEPTNO_SEQ;
```

Drop the trigger before the sequence it depends on, or explicitly handle the
dependency

## Extension exercises

The practical asks for an employee identifier such as `ENG5`, combining the
first three department-name characters with a per-department sequence number

That design needs to decide how concurrent inserts obtain distinct numbers
inside one department, not merely how to concatenate strings

It also revisits the cross-row salary rule from Practical 2, which a trigger can
check when either an employee or manager salary changes

## Checkpoint

- inserts that omit the generated key receive the expected next value
- existing constraints still reject invalid generated rows
- catalogue queries show only the intended user triggers
- cleanup removes both triggers and sequences without leaving dependencies
