# Week 5 - Direct Solution of Linear Systems

## Linear Systems

Many engineering models reduce to simultaneous linear equations

$$
A\mathbf{x}=\mathbf{b}
$$

| Quantity                     | Meaning                      |
| ---------------------------- | ---------------------------- |
| $A\in\mathbb{R}^{n\times n}$ | Known coefficient matrix     |
| $\mathbf{x}\in\mathbb{R}^n$  | Unknown solution vector      |
| $\mathbf{b}\in\mathbb{R}^n$  | Known right-hand-side vector |

Examples include truss equilibrium, electrical networks, discretised
differential equations and optimisation models

> [!EXAM] Form the system carefully
>
> 1. Choose and state the order of the unknowns in $\mathbf{x}$
> 2. Write one conservation or equilibrium equation at a time
> 3. Move unknown terms to the left and known terms to the right
> 4. Place each coefficient in the matching column of $A$
> 5. Check units and signs before solving

## NumPy Arrays

Numerical linear algebra uses `numpy.ndarray`, not nested Python lists

```python
import numpy as np

A = np.array(
    [
        [4.0, -2.0, 1.0],
        [-3.0, -1.0, 4.0],
        [1.0, -1.0, 3.0],
    ]
)
b = np.array([15.0, 8.0, 13.0])
x = np.linalg.solve(A, b)
```

Useful distinctions

| Expression | Meaning                              |
| ---------- | ------------------------------------ |
| `A * B`    | Elementwise multiplication           |
| `A @ B`    | Matrix multiplication                |
| `A.T`      | Transpose view                       |
| `A.copy()` | Independent copy                     |
| `A[1, :]`  | View of the second row in most cases |

> [!WARNING] Views share data
>
> ```python
> row = A[1, :]
> row += 2
> ```
>
> This also changes the second row of `A`

## Direct Methods

Direct methods reach the solution after a finite sequence of row operations,
apart from floating-point error

Allowed elementary row operations are

1. interchange two rows
2. multiply a row by a nonzero scalar
3. add a multiple of one row to another

Direct methods are well suited to small or dense systems, but elimination can
destroy sparsity and needs about $O(n^3)$ operations for a large $n\times n$
system

## Gauss-Jordan Elimination

Form the augmented matrix

$$
\left[A\mid\mathbf{b}\right]
$$

and apply row operations until

$$
\left[A\mid\mathbf{b}\right]
\longrightarrow
\left[I\mid\mathbf{x}\right]
$$

### Algorithm

For each pivot column $j$

1. choose a pivot row $p\ge j$
2. swap rows $p$ and $j$
3. divide row $j$ by the pivot $c_{jj}$
4. eliminate column $j$ from every other row

The elimination step for row $i\ne j$ is

$$
R_i\leftarrow R_i-c_{ij}R_j
$$

### Partial Pivoting

Choose the largest-magnitude available entry in the pivot column

$$
p=\operatorname*{arg\,max}_{i\ge j}|c_{ij}|
$$

Partial pivoting

- prevents division by a zero pivot when a row exchange can fix it
- reduces element growth and round-off amplification
- does not make a singular system solvable

> [!WARNING] Direct and iterative conditions differ
>
> Diagonal dominance is useful for iterative convergence but is not required
> by Gauss-Jordan elimination
>
> A zero leading diagonal entry calls for pivoting, not a convergence test

### Singularity Test

Never rely on exact floating-point equality with zero

```python
if abs(pivot) < 1.0e-16:
    raise ValueError("matrix is singular or nearly singular")
```

The threshold should be interpreted relative to the scale of the matrix in a
production solver

### Minimal Implementation Pattern

```python
def gauss_jordan(A, b):
    c = np.column_stack((A.astype(float), b.astype(float)))
    n = len(b)

    for j in range(n):
        pivot_row = j + np.argmax(np.abs(c[j:, j]))
        if abs(c[pivot_row, j]) < 1.0e-16:
            raise ValueError("matrix is singular or nearly singular")

        pivot = c[j].copy()
        c[j] = c[pivot_row]
        c[pivot_row] = pivot
        c[j] /= c[j, j]

        for i in range(n):
            if i != j:
                c[i] -= c[i, j] * c[j]

    return c[:, -1]
```

## LU Decomposition

Gauss-Jordan eliminates above and below every pivot

LU decomposition stops after producing an upper-triangular system and stores
the elimination multipliers in a lower-triangular matrix

With pivoting

$$
PA=LU
$$

where

- $P$ records row permutations
- $L$ is lower triangular with unit diagonal
- $U$ is upper triangular

To solve $A\mathbf{x}=\mathbf{b}$

$$
L\mathbf{y}=P\mathbf{b}
$$

followed by

$$
U\mathbf{x}=\mathbf{y}
$$

### Forward Substitution

For a unit-diagonal lower-triangular matrix

$$
y_i=b_i-\sum_{j=0}^{i-1}L_{ij}y_j
$$

### Back Substitution

For an upper-triangular matrix

$$
x_i
=
\frac{1}{U_{ii}}
\left(
y_i-\sum_{j=i+1}^{n-1}U_{ij}x_j
\right)
$$

Work from $i=n-1$ back to $i=0$

> [!EXAMPLE]- LU with one row permutation
> Consider
>
> $$
> A=
> \begin{bmatrix}
> 0&1&2\\
> 2&4&6\\
> 4&2&4
> \end{bmatrix},
> \qquad
> \mathbf b=
> \begin{bmatrix}3\\11\\10\end{bmatrix}
> $$
>
> Swap the first and third rows, then eliminate to obtain
>
> $$
> L=
> \begin{bmatrix}
> 1&0&0\\
> \tfrac12&1&0\\
> 0&\tfrac13&1
> \end{bmatrix},
> \qquad
> U=
> \begin{bmatrix}
> 4&2&4\\
> 0&3&4\\
> 0&0&\tfrac23
> \end{bmatrix}
> $$
>
> Apply the same permutation to $\mathbf b$
>
> $$
> P\mathbf b=
> \begin{bmatrix}10\\11\\3\end{bmatrix}
> $$
>
> Forward and back substitution give
>
> $$
> \mathbf x=
> \begin{bmatrix}1\\0\\\tfrac32\end{bmatrix}
> $$

### Why Reuse LU

The decomposition depends on $A$, not on $\mathbf b$

For several systems

$$
A\mathbf{x}^{(1)}=\mathbf{b}^{(1)},
\quad
A\mathbf{x}^{(2)}=\mathbf{b}^{(2)},
\quad\ldots
$$

decompose $A$ once, then repeat only forward and back substitution

| Stage                 | Approximate cost |
| --------------------- | ---------------: |
| Decomposition         |         $O(n^3)$ |
| Each triangular solve |         $O(n^2)$ |

## Choosing a Solver

| Situation                       | Appropriate approach                                    |
| ------------------------------- | ------------------------------------------------------- |
| One small dense system          | `numpy.linalg.solve` or pivoted elimination             |
| Same $A$, many right-hand sides | Reuse an LU decomposition                               |
| Need $A^{-1}$ itself            | Solve against identity columns only when truly required |
| Large sparse system             | Prefer an iterative or sparse direct method             |
| Over-constrained system         | Use least squares rather than ordinary elimination      |

> [!NOTE] Do not form the inverse to solve
>
> Computing $A^{-1}\mathbf b$ performs extra work and usually loses numerical
> accuracy compared with solving $A\mathbf x=\mathbf b$ directly

## Verification

Compute the residual

$$
\mathbf r=A\mathbf x-\mathbf b
$$

A small residual supports the result, but an ill-conditioned system may still
have a large solution error even when the residual is small

```python
residual = A @ x - b
assert np.linalg.norm(residual, np.inf) < 1.0e-10
```

> [!EXAM] Hand-worked solution checklist
>
> - show every row exchange
> - record each elimination multiplier
> - apply permutations to the right-hand side
> - use the updated row values in the intended order
> - finish with forward and back substitution for LU
> - verify by substituting into the original equations

---

> [!NOTE] Key ideas
>
> - A linear engineering model can be written as $A\mathbf x=\mathbf b$
> - Gauss-Jordan reduces the augmented matrix to $[I\mid\mathbf x]$
> - Partial pivoting improves reliability and handles removable zero pivots
> - LU stores elimination so it can be reused for new right-hand sides
> - Direct elimination costs about $O(n^3)$ and can destroy sparsity
> - Always verify the solution against the original system
