# Security Policy

## Supported version

Only the current default branch and published site are supported. Old
commits, local copies, and forks are not maintained.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that exposes secrets, private
data, or a practical exploit.

Use the repository's private vulnerability reporting option if it is
available. Otherwise, contact the maintainer, `@keys-i`, through an existing
private channel before sending sensitive details.

Include:

- a short description of the problem and its impact
- the affected page, file, workflow, or dependency
- the minimum steps needed to reproduce it
- relevant logs or a proof of concept with secrets removed

Content mistakes, broken links, and ordinary rendering problems are not
security vulnerabilities; use an issue template for those.

This is a personal static-notes site, so responses are best effort and no
formal response time is guaranteed.
